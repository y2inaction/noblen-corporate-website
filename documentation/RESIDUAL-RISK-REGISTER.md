# Known limitations and residual-risk register

As of commit `7228471` (application code `28bbdbd`), reviewed again at the tip of this documentation set. Severity and impact are the implementer's judgement for a corporate site that has not launched.

**How to read the mitigation column.** Each mitigation is labelled by what it actually is:

* **App (tested)**: implemented in the plugin or theme **and** covered by an automated test cited in the row.
* **App (untested)**: implemented but not directly tested. None is relied on here.
* **Host**: a control that must be configured on the real host or CDN. It is **not implemented in this repository and not tested here**; the repository only documents it ([DEPLOYMENT.md](DEPLOYMENT.md)).
* **Process**: a human action or decision. Not implemented by software.
* **None**: nothing mitigates it yet.

**Disposition.** "Open" means the risk is carried and documented. **No risk in this register has been accepted by the owner**; "carried" never means accepted. The owner decides in [OWNER-DECISION-REGISTER.md](OWNER-DECISION-REGISTER.md).
