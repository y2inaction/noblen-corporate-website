## 1. Purpose

Exercise the rule that a database upgrade refuses to run until a backup is confirmed. No earlier release exists, so the older schema is a staging fixture made on purpose; this record tests the workflow and does not claim that an earlier version was ever released. The commands are `wp noblen migrate ...`; run them with `--user=<login>` of an administrator.

## 2. Prerequisites

- A staging copy of WordPress 6.4 or newer on PHP 8.3 or newer, built from the release packages (`scripts/build-packages.sh`: `noblen-corporate-theme.zip`, `noblen-corporate-core.zip`, `SHA256SUMS`), never production. WP_DEBUG and WP_DEBUG_LOG on so that PHP problems are recorded.
- WP-CLI on the staging server. A fresh backup. An administrator login and an approver login. This is developer-assisted: steps 2 and 3 change the staging database on purpose.
